# 인수인계 (2026-10-26 기준)

개발·배포 방법은 [DEVELOPMENT.md](DEVELOPMENT.md)를 보세요. 이 문서는 **지금 어디까지 했고 다음에 뭘 할지**만 적습니다.
허브·기기·채널 ID는 공개 저장소라 적지 않았습니다. `smartthings devices`, `smartthings edge:channels`로 확인하세요.

## 현재 상태

| 항목 | 상태 |
|---|---|
| NEO Motion Sensor | 정상. 주말 동안 118분 가짜 감지 0건 통과 (감지 103건 중) |
| AOYAN 센서 | 주기적으로 "죽음" → 일요일 새벽부터 오프라인 |
| 허브에 설치된 AOYAN용 드라이버 | **Zigbee Motion Sensor Mc (AOYAN)** (`aoyan-mariano/`) |
| `aoyan-motion` (우리 드라이버) | 허브에서는 지움. 채널·저장소에는 남아 있음 (마지막 수정 `ed1e163`) |

### AOYAN 센서가 죽는 원인 (추정, 미확인)

- 센서가 **주방 간접등(Zigbee 전구)을 중간 연결 기기로 사용** 중. 일부 전구는 배터리 센서를 연결 목록에서 빼 버림.
- 허브의 **Zigbee 보안 모드가 켜져 있어**(unsecure rejoin 꺼짐) 싸구려 Tuya 기기가 다시 붙지 못할 수 있음.
- 같은 기간 배터리 버튼(조명 전체 스위치)은 정상 → 센서와 그 연결 경로 문제일 가능성이 큼.

## 다음에 할 것 (집에서)

1. **주방 간접등(과 주방불) 전원을 뽑는다.** 센서가 허브에 직접 붙게 하려는 것.
2. 허브 근처에서 AOYAN 센서를 **다시 페어링** → 드라이버가 "Zigbee Motion Sensor Mc (AOYAN)"으로 잡혔는지 확인.
3. 페어링 후 간접등을 다시 꽂는다.
4. 며칠 지켜본다.
   - 이 드라이버에서도 죽으면 → 드라이버 문제가 아니라 네트워크 문제. 보안 모드 끄기를 검토.
   - 안 죽으면 → `aoyan-motion`과 차이를 비교.
5. 가능하면 `smartthings edge:drivers:logcat`을 켜 두고 Tuya 시간 동기화 요청(EF00 클러스터 명령 0x24)이 오는지 본다. 오면 응답 구현을 검토.

## 확인 안 된 것

- Mariano 드라이버가 실제 AY-204Z에서 모션·배터리를 잘 받는지 (빌드·설치만 확인).
- Zigbee2MQTT 자료상 AY-204Z에 **조도 센서**가 있다고 함. 두 드라이버 모두 지원 안 함.
- 와이파이 2.4GHz 채널 간섭 여부 (Zigbee 14번 채널은 와이파이 1~4번과 겹침).
